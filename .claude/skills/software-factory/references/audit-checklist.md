# 工場の監査と点検

新規構築の後は「生成後の点検」を、運用中の工場は「監査」を行う。

## 生成後の点検

- [ ] architecture-selection のハーネスがあり、`make check` が通る。コマンドの入口が `Makefile` に一つで、エージェントが `pnpm` や各ツールを直接叩くと拒否される
- [ ] `.claude/agents/` に 4 つの役割があり、`reviewer` のツールに Edit と Write がない
- [ ] `/spec`、`/build`、`/review`、`/retro` が使える
- [ ] `.claude/settings.json` に、権限(allow / ask / deny)とフック(PreToolUse 2 つ、PostToolUse、Stop)がある
- [ ] `guard-bash.sh` が `git push --force` を終了コード 2 で拒否する
- [ ] `guard-paths.sh` が `.claude/agents/reviewer.md` への書き込みを拒否する
- [ ] `docs/factory/README.md` の角括弧が埋まっている
- [ ] ARCHITECTURE.md の「編集制約」に、工場が追加した保護パスと仕組みが書かれ、工場の導入が ADR にある
- [ ] 採った形式の無人ジョブ(形式 A: 2 つのワークフロー、形式 B: 2 つのルーティンと pre-push)と `secrets-scan` があり、必要なシークレット、ルーティン、ブランチ保護を人に依頼した
- [ ] `factory/review` が必須チェックで、ブランチ保護の迂回を許すリストが空になっている
- [ ] `post-review.sh` が手元のセッションでは拒否される(`FACTORY_JOB` がないとき)

## 監査

### ガードレール
- [ ] 止めたいことが、指示以外の二つ以上の層で止められている(references/guardrails.md の表)
- [ ] ガードレールの設定ファイルが保護パスで、CODEOWNERS の対象になっている
- [ ] 権限の許可リストに、破壊的な操作や外部への送信が入っていない
- [ ] 形式 A: GitHub Actions のエージェントに、工程に要らないツールが与えられていない
- [ ] 形式 B: ルーティンにコネクタがなく、レビューの GitHub トリガーが信頼できる作成者に絞られている
- [ ] Git のフックで行う検査が、すべて GitHub 側でも行われ、必須チェックになっている(`--no-verify` で回避してもマージできない)
- [ ] 秘密情報の検出が、コミット前と CI の両方で動いている

### 工程
- [ ] 直近の PR の多くが仕様にひも付いている。仕様のない PR は「工程を省いてよい場合」に当たる
- [ ] 承認されていない仕様で実装した PR がない
- [ ] PR の受け入れ条件とテストの対応表が埋まっている
- [ ] reviewer の必須の指摘が、マージ前に解消されている

### 改善ループ
- [ ] `/retro` の記録が、PR に含まれている
- [ ] 週次の改善ジョブ(Actions かルーティン)が直近 4 週動き、報告が残っている
- [ ] 回数が 2 以上のまま 4 週以上放置された記録がない
- [ ] 昇格した規則に、効き目を示す例(違反する fixture やテスト)が付いている
- [ ] 規則を緩める変更が、Issue と ADR を経ずに入っていない
