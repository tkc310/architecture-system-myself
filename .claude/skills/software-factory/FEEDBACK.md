# このスキルへのフィードバック

工場を構築・運用して合わなかった点を記録する。同じ種類が 2 回出たら `SKILL.md`、`references/`、`templates/` を直す。編集はユーザーの承認を得てから PR で行う。

| 日付 | 案件(概要) | 種類 | 内容 | 対応 |
| --- | --- | --- | --- | --- |
| | | | | |

種類: 工程の抜け、役割の境界、ガードレールの穴、ガードレールが強すぎる(作業が止まりすぎる)、改善ループの停滞、ツールの変化(Claude Code や GitHub Actions の仕様の変更)

見直しの観点:
- Claude Code の設定形式(サブエージェント、スキル、権限、フック)と claude-code-action の入力が、現行の公式ドキュメントと一致しているか
- `guard-bash.sh` が止めすぎて、人の確認が増えすぎていないか。止め漏れはなかったか
- 週次の改善ジョブの PR のうち、採られなかったものの理由に偏りはないか
