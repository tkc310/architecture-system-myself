# {{プロジェクト名}} エージェント向けルール

> ここには**機械で強制できないルールだけ**を書く。lint・型・依存ルール・テストで守れるものは、そちらに書く。
> 同じ指摘が 2 回出たら `docs/feedback/LESSONS.md` に記録し、機械的ルールへの昇格を検討する。

## 最初に読むもの
- `docs/architecture/overview.md`:現在の構成(アーキタイプ: {{L1 / L2 / L3}})
- `docs/adr/`:決定とその理由。ADR と矛盾する変更をする場合は、先に新しい ADR を提案する

## コマンド
| 目的 | コマンド |
|------|----------|
| すべての検査(完了前に必ず実行) | `pnpm check` |
| 型検査 | `pnpm typecheck` |
| lint / format | `pnpm lint` / `pnpm format` |
| 境界ルール | `pnpm lint:deps` |
| テスト | `pnpm test` |

## 作業ルール
- 作業の完了を報告する前に `pnpm check` を通す。通らない状態で完了と言わない。
- 検査を通すためにルールを無効化しない(`biome-ignore`、`@ts-expect-error`、依存ルールの除外追加など)。必要と考えたら理由を添えて人に確認する。
- 新しい依存パッケージを追加する前に、既存の依存や標準機能で済まないか確認し、追加理由を PR 説明に書く。
- アーキタイプが要求しない層(L1 でのリポジトリ層やドメイン層など)を作らない。必要だと感じたら ADR の昇格条件を確認し、提案する。
- 入力の型はスキーマ({{Zod / Effect Schema}})から導出する。同じ形の型を手で書かない。
- 生成物(`packages/contracts/` など)を手で編集しない。

## 禁止事項
- 秘密情報(API キー、トークン、個人情報)をコード・ログ・テストデータに書かない。
- `main` へ直接 push しない。
- マイグレーションを適用済みのものに対して書き換えない(新しいマイグレーションを追加する)。

## 間違いを見つけたら
- 自分や他のエージェントの誤りに気づいたら、`docs/feedback/LESSONS.md` に 1 件追記する(形式はファイル内の説明に従う)。
