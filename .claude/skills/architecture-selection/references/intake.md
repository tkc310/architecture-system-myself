# 聞き取り質問票

一度に最大5問。優先度順に並べてある。答えがない場合は「既定値」を採用し、ADR の「前提」に書く。

| 優先 | 質問 | 判定に使う箇所 | 既定値 |
|------|------|----------------|--------|
| 1 | 何を作るか。主な利用者と主要な操作(上位3つ)は? | 全体 | — (必須。既定なし) |
| 2 | 業務ルールはどの程度複雑か。入力検証だけで済むか、状態遷移・不変条件・計算ロジックがあるか? | L1/L2/L3 | 入力検証中心 |
| 3 | 独立して変化する業務領域(例:会員、課金、在庫)はいくつあるか? | L1/L2 | 1〜2 |
| 4 | 開発する人数・チーム数、想定する保守期間は? | L2/L3 | 1〜3人、1年程度 |
| 5 | 性能要件は?(p95 レイテンシ、ピーク RPS、データ量、CPU を使う処理の有無) | 性能段 P0〜P4 | 一般的な Web 要件(p95 < 500ms、数十 RPS) |
| 6 | 画面は必要か。SEO・SSR は必要か? API のみか? | 技術スタック | 画面あり、SSR 不要 |
| 7 | デプロイ先の制約は?(Vercel / Cloudflare / AWS / 社内基盤 / 指定なし) | 技術スタック | 指定なし |
| 8 | リアルタイム通信、バックグラウンドジョブ、マルチテナント、外部公開 API は必要か? | 修飾子 | 不要 |
| 9 | 既存の資産・組織標準(DB、認証基盤、言語)はあるか? | 技術スタック | なし |
| 10 | 外部クライアント(モバイル、他社、Go サービス)がこの API を使うか? | API 契約 | 使わない |

## 回答の解釈のヒント

- 「CRUD 管理画面」「社内ツール」「LP + フォーム」→ 多くは L1。
- 「承認フロー」「料金計算」「在庫引当」など、**同じルールを複数の入口から守る必要がある** → L2 以上を検討。
- 「数値計算・画像/動画処理・圧縮・暗号・大量パース」→ CPU 処理あり。性能段 P2 以上を検討。
- 「同時接続が多い」「外部 API を大量に並行で叩く」→ I/O 並行性。性能段 P1。
